# Implementation Plan: Module 2 - Backend API (Express + MySQL + Prisma + Google Gemini)

**Branch**: `module/backend-api` | **Date**: 2026-09-12 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-backend-api/spec.md`

---

## 1. Summary

Module 2 delivers the full production Express backend for CareerPrepster, orchestrating MySQL 8.0 with Prisma ORM, standard JWT authentication in HttpOnly cookies, atomic CV CRUD transactions, in-memory PDF/DOCX text extraction (`pdf-parse` + `mammoth`), stateless AI wording enhancement via Google Gemini (STAR/XYZ framework), a deterministic 4-pillar ATS scoring engine, a pre-seeded Job Role catalog (15+ graduate roles, 50+ bullets), and seamless frontend integration to replace all client-side mocks.

All backend components are containerized via Docker Compose alongside MySQL and the Next.js frontend, utilizing shared Zod validation schemas.

---

## 2. Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20 LTS  
**Backend Framework**: Express.js 4.x (`cors`, `helmet`, `cookie-parser`, `morgan`)  
**Database & ORM**: MySQL 8.0, Prisma ORM 5.x  
**Authentication & Security**: JWT (`jsonwebtoken`) in `HttpOnly, Secure, SameSite=Lax` cookie, `bcryptjs` password hashing  
**Validation**: Zod 3.x (shared client & server contracts)  
**File Parsing & Upload**: `multer` (RAM memory storage, 5MB limit), `pdf-parse` (PDF text extraction), `mammoth` (DOCX extraction)  
**AI Service Integration**: Google Gemini 2.5 Flash API via `@google/genai` (structured JSON schema output, stateless execution, exponential backoff retries)  
**ATS Scoring Algorithm**: 100% Deterministic Rule-Based Engine (4 pillars, 250+ power verbs, regex metric detectors, keyword matcher)  
**Containerization**: Docker Compose (`mysql:8.0`, `backend`, `frontend`), Multi-stage Dockerfiles  
**Target Platform**: Linux containers, Node.js 20 runtime  
**Performance Goals**:
- Auth cookie verification (`requireAuth`): `< 1ms`
- Job role catalog indexed search: `< 50ms`
- CV nested tree fetch (`GET /api/cvs/:id`): `< 30ms`
- ATS scoring calculation: `< 10ms`
- PDF/DOCX text extraction: `< 100ms`
- Google Gemini AI bullet rewrite: `< 2.5s`
- Google Gemini AI resume structuring: `< 3.5s`

### Phase Breakdown

1. **Phase 1: Infrastructure & Scaffolding**
   - Goal: Configure root `docker-compose.yml` (MySQL 8.0, backend container, frontend container) and initialize `backend/` with Express, TypeScript, ESLint, and healthcheck route `GET /api/health`.
   - Verification: `docker compose up -d` boots all containers; `curl http://localhost:5000/api/health` returns `200 OK`.

2. **Phase 2: Database Schema & Seed Data**
   - Goal: Define complete `prisma/schema.prisma`, run initial migration, and author `prisma/seed.ts` containing 15+ high-demand graduate job roles and 50+ pre-curated STAR/XYZ bullets.
   - Verification: `npx prisma db seed` successfully creates rows; verified via MySQL client.

3. **Phase 3: Shared Schemas & Core Middlewares**
   - Goal: Implement shared Zod validation schemas in `shared/src/schemas/`, create generic `validate()` middleware, `requireAuth()` JWT verification middleware, and `errorHandler()` global error boundary.
   - Verification: Unit test middleware responses with valid/invalid tokens and malformed payloads.

4. **Phase 4: Authentication System**
   - Goal: Implement `auth.service.ts`, `auth.controller.ts`, and `auth.routes.ts` (`POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`) with `bcryptjs` and `HttpOnly` JWT cookie issuance.
   - Verification: Test register/login/me/logout flow via `curl` with cookies.

5. **Phase 5: Stateless AI Wording Assistant (Google Gemini)**
   - Goal: Implement `ai.service.ts` integrating Google Gemini 2.5 Flash with structured `responseSchema`, exponential retry logic, and `POST /api/ai/enhance-bullet` controller/route.
   - Verification: Calling endpoint with raw bullet returns 2-3 structured suggestions with power verbs and metrics.

6. **Phase 6: Deterministic ATS Scoring Engine**
   - Goal: Implement `ats.service.ts` evaluating 4 pillars (Parsability, Impact, Skills, Brevity) and JD keyword matching; save `ATSReport` row in MySQL.
   - Verification: Calling `POST /api/ats/score` returns deterministic 0-100 score; running twice on same CV yields identical result.

7. **Phase 7: Resume Import & Text Parsing**
   - Goal: Implement `parser.service.ts` with `multer` RAM storage, `pdf-parse`, and `mammoth`; pipe extracted text to Gemini structured layout parser; handle scanned PDF detection (<30 chars).
   - Verification: Uploading digital PDF/DOCX returns structured CV JSON; scanned PDF returns `422`.

8. **Phase 8: CV CRUD & Job Role Catalog**
   - Goal: Implement `cv.service.ts` using Prisma `$transaction` for atomic tree updates, and `job-role.service.ts` for indexed keyword search.
   - Verification: Full CRUD cycle (`POST`, `GET`, `PUT`, `DELETE /api/cvs/:id`) works flawlessly.

9. **Phase 9: Frontend Full Integration**
   - Goal: Update `frontend/src/lib/api.ts` to call Express backend (`credentials: "include"`), remove Next.js temporary import route, and verify complete user journey in browser.
   - Verification: User can register, create CV, browse starter bullets, enhance with AI, import PDF, and score ATS report end-to-end.
